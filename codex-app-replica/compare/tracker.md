# Codex App Replica Tracker

## Purpose

- This tracker is page-first and single-page-driven.
- The only allowed execution loop is:
  1. extract and confirm one page from the current baseline resources
  2. register that page in this tracker
  3. decompose only that page into concrete feature points
  4. compare the replica against that page
  5. close that page's gaps
  6. verify that page
  7. only then move to the next page
- Do not run broad module-wide, cross-page, or intuition-driven work outside this loop.

## UI Parity Audit Tracker

- Companion file: `compare/ui-parity-tracker.md`
- Purpose: records source-vs-source UI parity for entries already marked `done` here, since many `done` rows only certified the Rust/Tauri bridge and not the React UI render.
- This tracker remains the page-lifecycle source of truth. The audit tracker only holds UI findings and repair plans; promoting an audit gap into a real `P-###-F##` row still requires user authorization.

## Hard Rules

- Tracker unit is `page`, not `module`, not `theme`, not `subsystem`.
- At most one page may be `in_progress` at a time.
- Do not prefill a broad feature inventory for the whole product.
- Do not add speculative future pages just because they seem adjacent.
- Only add a page after the current baseline resources prove that the page exists.
- Only add feature-point rows after the owning page row exists.
- Only implement work that belongs to the current page and its confirmed feature points.
- Shared code extraction or infrastructure work is allowed only if the current page strictly requires it.
- If shared work is required, keep it scoped to the current page and record that dependency inside the current page notes.
- If a page cannot be proven from extracted resources, do not track or implement it yet.
- If a page is blocked, record the blocker, stop that page, and only then choose the next page from extracted resources.
- Do not resume old tracker entries from the previous reset. Re-prove everything against the current extracted version.

## Source Of Truth

- Primary and mandatory first method: resource extraction from `compare/resources/26.506.2212.0/app.asar.extracted/`
- Only if resource extraction is insufficient for the current page:
  1. network packet capture
  2. protocol observation
- Do not use current replica behavior as tracker evidence.
- Do not use old screenshots, old tracker rows, or old notes as tracker evidence unless they point to current-version extracted artifacts or newly captured allowed evidence.

### Feature Point Row Fields

- `ID`
- `Status`
- `Feature Point`
- `Upstream Evidence`
- `Replica Targets`
- `Gap`
- `Blocked Reason`
- `Notes`

## Required Workflow

1. Inspect current extracted resources and choose one concrete page owner bundle.
2. Confirm the exact upstream page file path or page owner file set.
3. Add one page row under `Current Page`.
4. Read that page's extracted resources and enumerate only the feature points that belong to that page.
5. Add feature-point rows nested under that page.
6. For each feature point, record the current replica target files and the concrete gap.
7. Implement and verify only those rows.
8. When all feature points for that page are `done` or the page is blocked, move the page row to `Completed Pages` or `Blocked Pages`.
9. Then and only then choose the next page.

## Forbidden Workflow

- No parallel multi-page execution.
- No global “scan everything then work later” tracker expansion.
- No module-wide progress claims.
- No cross-page cleanup for convenience.
- No speculative abstractions based on future pages.
- No feature work without an owning current page row.
- No page switching before the current page is completed or blocked.
